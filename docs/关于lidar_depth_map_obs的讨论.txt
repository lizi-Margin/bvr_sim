GPT:
1) 先做“点检测” → 物体列表（object-centric） → Set / GNN / Transformer

思路：先把 ray-grid 做局部聚合（例如连续非零 ray 串或峰值检测）得到目标候选（每个目标：方位、仰角、距离、径向速度、锁定、导弹标志等）。把环境表示成不定长目标集合（N targets），然后用 DeepSets / Set Transformer / GNN/Relation Net 去处理目标间交互与决策输入。
优点：

非常符合“每个像素代表一个敌机”的事实，去掉大量无用稀疏信息。

更具可解释性（每个节点是“一个飞机/导弹”）。

GNN/Set 模型对交互建模（友军/敌军/导弹）很有效，且样本效率高。
缺点：

需要一个稳定的目标检测/群聚步骤（可能需要阈值/滤波、短暂丢失的处理）。

如果目标遮挡/检测错误，需要鲁棒处理（masking、置信度）。
何时用：目标数通常较少（BVR 中通常几十以下），而且你关心对象关系时强烈推荐。

2) Per-ray embedding + 1D 卷积（或轴向 separable conv）

思路：对每条 ray 做一个小 MLP（或线性层）映射到 embedding，然后在方位轴上做 1D 卷积（每个仰角层单独处理或跨仰角做 separable conv）。方位轴用 circular padding（处理 360° wrap-around）。
优点：

保留局部相邻关系（邻近 ray 的信息能被捕获）。

计算低、参数少，比 2D 卷积更合理（因为 elevation bins 少）。

卷积对稀疏点仍能利用“局部相邻的证据”。
缺点：

对很远的非局部交互（例如两个相距很远的目标的关系）需要大感受野或后接 Transformer/GNN。
何时用：当 ray-grid 真正是连续角度采样且你想要一个轻量的、位置感知的前端。

3) Attention / Transformer，但用相对位置编码或 RoPE、以及局部化偏置（local attention）

思路：先把每 ray 的特征嵌入（含角度坐标），用 Transformer，但是不要只用绝对 learned pos embedding。建议使用：

相对位置编码（relative pos）：关注“两个 ray 间的角差”而非绝对索引；对旋转平移（旋转围绕自身）更稳健。

RoPE（rotary）：对角度周期性处理较好。

混合 attention：局部 attention + 若干 global tokens（例如引入 few global summary tokens 或稀疏 attention），以降低计算且保留长程交互。
优点：

可以直接表达任意长交互与关系。

保留 permutation-invariant 的灵活性并用相对编码恢复位置信息。
缺点：

训练样本效率较低（尤其在 sparse reward 场景）。

实现需注意 wrap-around（相对 pos 计算要按圆周差处理）。

4) CoordConv / 多通道位置注入（在每个 ray 上显式加角度坐标）

思路：在 per-ray feature 中加入（sin(az), cos(az), sin(el), cos(el)）或原始角度数值，或者使用 CoordConv（即把坐标作为额外通道传入 conv/MLP）。
优点：

简单有效，特别是当你仍想保留 MLP 的便利性时。

对模型学习位置信息更直接，比无位置输入的 MLP 好很多。
缺点：

仍然是“显式依赖学习”，可能需要更多数据去学相对关系。
何时用：作为 baseline，几乎应当至少试验。
